## Code and contract findings

1. **Required — boards containing four to six images hide real photos.** `selectBoardLayout` caps the chosen layout at three even though `VISION_BOARD_MAX_IMAGES` is six. `useVisionBoardScene` then slices the order to `layout.photos.length`; `VisionBoardScene` excludes nonordered photos. Adding a fourth image can therefore persist it without displaying it on the board. This cap predates the new Detail selector, but the new Detail selector inherits it. Provide Detail compositions for every supported count or render every extra real photo through an explicitly defined continuation. Verify four-, five- and six-photo boards and reordering; do not silently lower capacity or delete scenes. This is a contract issue beyond the three-photo visual score.

2. **Required — caption can clip at its accepted length.** `VisionBoard` places an unrestricted wrapping caption at 83% of an overflow-hidden viewport, width 30% of the board, with only two font sizes. An 80-character caption can need more lines than the remaining board height, especially on narrow phones or with increased text scale. Reserve caption space using measured line height/line count or move it into a bounded caption row that grows with user text. Preserve the persisted title and do not silently truncate it.

3. **Required — unbroken long description is not actually bounded.** `truncateVisionText` falls back to `text.length` when no whitespace/sentence breakpoint exists. A long single token returns the entire text plus ellipsis. Use the requested character limit as the final fallback, and verify long unbroken input plus normal sentence/word boundaries. This edge case is distinct from the photographed fixture.

4. **Interaction verification remains open.** At the first source read, the newly added hold used `Race(pan, hold, tap)` with the pan eligible before the hold. During this review the working source changed to `Race(Simultaneous(pan, hold), tap)` with `maxDistance(8)`. The earlier observation is therefore superseded as a current-code finding. The supplied `longpress.png` remains a whole-board capture and cannot prove that current stationary holds reveal the image actions. Verify the final gesture wiring on Android with both a stationary hold and an actual drag, and check scroll resumes after release. Do not award this based on the changed source alone.

The screen takes annotation from `model.vision.title`, updates it through `model.updateVision`, and obtains Chart summary from the existing Chart adapter. App exposes the QA host only behind `__DEV__`. These are appropriate data boundaries for the reviewed work; no fabricated production caption or progress was found in that wiring.
